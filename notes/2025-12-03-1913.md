Bazel hermeticity
=================

If we want hermeticity, we need to add the following to our `.bazelrc` file
([docs](https://bazel.build/reference/command-line-reference#flag--incompatible_strict_action_env)):

```
build --incompatible_strict_action_env
```

> If true, Bazel uses an environment with a static value for `PATH` and does not inherit
> `LD_LIBRARY_PATH`. Use `--action_env=ENV_VARIABLE` if you want to inherit specific
> environment variables from the client, but note that doing so can prevent cross-user
> caching if a shared cache is used.

As a side effect, **some of the commands that are used in the tests could be missing from
this hardcoded `PATH` variable**. To fix it, we need to provide our own `PATH` value
adding an entry to the `user.bazelrc` file listing all the directories needed to
find all the tools:

For example, here I'm adding the path to rancher-desktop so it will find `docker` command:

```
test --action_env=PATH=/Users/jgsogo/.rd/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
```

---

To help developers, we are adding some tests to `bazel/tools/tests` that will fail if the
commands we need are not available. The error messages should provide enough information
to fix it.
