`rules_rust` and binary-only packages
=====================================

In order to support crates that doesn't define a library, we need to implement a different approach
(see [docs](https://bazelbuild.github.io/rules_rust/crate_universe.html#binary-dependencies)):

> Neither of the above approaches supports depending on binary-only packages.

Here I'm writing my own build target:

1. In the `MODULE.bazel` file I use `http_archive` to fetch the content of the crate.

   Note that I can get it from `crates.io` instead of Github... and if we look at the sources,
   the `Cargo.toml` file of the crate downloaded from `crates.io` is not exactly the same
   as the one in the repository (paths to other crates in the same repository are resolved).

2. I add a `build_file` to the download so it knows how to build the binary. The content of this
   [`BUILD.diesel_cli.bazel`](../bazel/external/BUILD.diesel_cli.bazel) is pretty straightforward,
   just a `rust_binary` with some dependencies.

3. Here it comes the tricky part: **the dependencies**.

   I didn't manage to implement a different _crate universe_ for this binary (TODO: Something to
   investigate and fix) so I added it to the same Cargo workspace as the rest of the libraries
   and applications:

   - I added the entry to the main [`Cargo.toml`](../Cargo.toml).
   - Added the corresponding [`Cargo.toml` file for the binary](../bazel/external/Cargo.toml). This
     file uses the dependencies from the workspace. **I need to _consume_ from this file all the
     dependencies that are not already consumed in other libraries or applications** (it looks like
     the dependencies that are not consumed, are not available).
   - Added the corresponding entry to `manifests` in the `crate.from_cargo` inside the `MODULE.bazel`.

Now I can reuse this same infrastructure for other future binary-only packages without needing
extra projects in the workspace.
