Rust: Testing errors
====================

```rust
let r: Result<T, Error> =...

assert!(r.is_err());
assert!(matches!(
    r.unwrap_err(),
    Error::DeserializationError(DeserializationError {
        source: DeserializationErrorKind::SerdeError { .. },
        string: ref msg,
    })if msg == "this is not serializable"
));
```

When testing the return error of some function, it's important to check the **type of the error and some input values
associated to it** more than the resulting error string:

* The specific **type** will be used by the caller in `match` expressions to deal with the error
* Input values won't be modified, as the inputs originating the error should be always the same in the test scenarios

However, the resulting string is something that we might want to improve (or translate) and it doesn't add any value
to a test suite. The `assert!(matches!(...))` pattern allow us to test exactly those fields.

> Note.- There is a `assert_matches` macro being standardized into the language (
> see [#82775](https://github.com/rust-lang/rust/issues/82775)).
