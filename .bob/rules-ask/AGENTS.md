# Ask Mode Rules

This file contains non-obvious documentation context for this monorepo.

## Project Structure (Counterintuitive)

- **Multi-app monorepo**: Contains 4+ independent apps (`board_games`, `finances`, `photodb`, `syncronia`) - each has different tech stack
- **Shared libraries**: `libraries/` contains reusable code across apps - check here before creating new utilities
- **Bazel as primary**: Even though Cargo.toml and package.json exist, Bazel is the source of truth for builds

## Documentation Locations (Non-Obvious)

- **App-specific docs**: Each app may have its own README.md or db.md (e.g., `apps/board_games/db.md`)
- **Build system docs**: Custom Bazel rules documented in their .bzl files (e.g., `bazel/rust/defs.bzl`)
- **Notes directory**: `notes/` contains dated markdown files with implementation decisions
- **Justfile commands**: Run `just` without args to see available commands (requires fzf)

## Generated Files (Don't Edit Directly)

- **schema.rs files**: Generated by Diesel CLI via `bazel run //<package>:<name>.update`
- **Protobuf TS files**: Generated and copied to workspace via `just update-npm`
- **BUILD files in bazel/third_party/crates**: Auto-generated by `crates_vendor`, then patched

## Workspace Organization

- **pnpm workspaces**: Defined in pnpm-workspace.yaml - not all TS packages are workspaces
- **Cargo workspace**: All Rust crates in workspace, but Bazel manages actual builds
- **node_modules paradox**: Exist in workspace for IDE, but Bazel uses separate copy in build directory

## Testing Context

- **Integration tests location**: Must be `tests/test_*.rs` for Rust (not nested directories)
- **Postgres tests**: Automatically get Docker container via `with_postgres_test()` wrapper
- **Test data split**: `test_compile_data` vs `test_data` distinction is critical for Bazel caching
